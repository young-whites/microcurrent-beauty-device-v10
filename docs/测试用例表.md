## Key Notes

- **Heating GPIO**: Small handle → PC10, Large handle → PC11 (NOT PC12)
- **54V Boost**: NOT enabled at boot; only enabled during electrical stimulation output
- **Shutdown Flow**: MCU sends shutdown request (func=0x0A) to host, waits for ACK; 5s timeout forces shutdown
- **Air Pump**: Simple ON/OFF control via PB10 (high=enable, low=disable), no PWM speed regulation
- **Test ID Format**: `P{Phase}-{Number}` (e.g. `P1-01`, `P2-01`)

## Phase 1: Power Supply & Boot Sequence

Tests for power-on/power-off flow and power management GPIOs.

### 1.1 Boot Sequence

- [ ] **P1-01** Power button detection: Press PA5 low for ≥1s → system detects stable button press
- [ ] **P1-02** LED indicator ON: After boot → PA6 outputs HIGH → LED lights up (steady on)
- [ ] **P1-03** Buzzer beep: After boot → PA7 outputs HIGH for 1s → buzzer sounds 1s then stops
- [ ] **P1-04** 12V power enable: After boot → PA4 outputs HIGH → 12V power rail enabled
- [ ] **P1-05** 54V boost NOT enabled: After boot → PB0=LOW, PB1=LOW → 54V boost disabled
- [ ] **P1-06** Boot sequence order: Button → LED → Buzzer 1s → 12V enable → verify timing sequence via debug log

### 1.2 Shutdown Sequence

- [ ] **P1-07** Shutdown request: Long-press PA5 → MCU sends func=0x0A shutdown request to host via UART1
- [ ] **P1-08** Shutdown ACK received: Host replies shutdown ACK → MCU proceeds to shutdown
- [ ] **P1-09** Shutdown output cutoff: On ACK → disable 54V boost (PB0/PB1=LOW), disable air pump (PB10=LOW)
- [ ] **P1-10** Shutdown 12V cutoff: After outputs off → PA4=LOW → 12V power rail disabled
- [ ] **P1-11** Shutdown buzzer: After power cutoff → PA7 HIGH for 1s → buzzer sounds once
- [ ] **P1-12** Shutdown LED off: After buzzer → PA6=LOW → LED turns off
- [ ] **P1-13** Shutdown timeout: No ACK from host within 5s → MCU forces shutdown regardless
- [ ] **P1-14** Shutdown while running: Running state → long-press → send shutdown request → verify outputs stop before power off

### 1.3 GPIO Independent Verification

- [ ] **P1-15** PA4 (12V enable): Set HIGH → 12V rail ON; set LOW → 12V rail OFF
- [ ] **P1-16** PA5 (Button): Default HIGH; press → LOW; release → HIGH
- [ ] **P1-17** PA6 (LED): Set HIGH → LED on; set LOW → LED off
- [ ] **P1-18** PA7 (Buzzer): Set HIGH → buzzer on; set LOW → buzzer off
- [ ] **P1-19** PB0 (54V boost 1): Set HIGH → LGS6302EP-1 enabled; LOW → disabled
- [ ] **P1-20** PB1 (54V boost 2): Set HIGH → LGS6302EP-2 enabled; LOW → disabled

## Phase 4: Communication Protocol (UART1)

Protocol frame parsing and command-level tests.

### 4.1 Frame Parsing & Validation

- [ ] **P4-01** Normal frame parsing: Send `55 AA 05 60 66 44 02 08 7D DE` → device parses correctly, returns version ACK
- [ ] **P4-02** CRC error detection: Modify CRC bytes → device discards frame, no ACK returned
- [ ] **P4-03** Invalid header: Send `56 AA ...` → device discards, state machine returns to IDLE
- [ ] **P4-04** Address mismatch: Change device address byte → device discards, no response
- [ ] **P4-05** Oversized frame: Send frame >64 bytes → device discards, no crash
- [ ] **P4-06** Undersized frame: Send incomplete frame (header only) → device discards, state machine timeout reset
- [ ] **P4-07** Consecutive frames: Rapidly send 10 different command frames → all parsed and ACKed correctly, no frame loss
- [ ] **P4-08** Ring buffer saturation: Flood UART RX with data → buffer drops new data when full, no overflow

### 4.2 CRC16-MODBUS Verification

- [ ] **P4-09** CRC correctness: Input `05 60 66 44 02 08` → CRC = `7D DE`
- [ ] **P4-10** CRC byte order: Known CRC `0x0F48` → frame bytes `0F 48` (big-endian, MSB first)

### 4.3 Version Read (func=0x08)

- [ ] **P4-11** Normal version read: Send `55 AA 05 60 66 44 02 08 7D DE` → ACK returns `01 00` (V1.0)
- [ ] **P4-12** Response in any state: Send version read while paused/running/aging → always returns version correctly

### 4.4 Handle Switch (func=0x01)

- [ ] **P4-13** Switch to Handle A: Send `55 AA 06 60 66 44 02 01 0A 0F 48` → ACK returns `0A`
- [ ] **P4-14** Switch to Handle B: Send `55 AA 06 60 66 44 02 01 0B CF 89` → ACK returns `0B`
- [ ] **P4-15** Switch to Handle C: Send `55 AA 06 60 66 44 02 01 0C 0D C8` → ACK returns `0C`
- [ ] **P4-16** Invalid handle ID: Send `func=0x01, para=0x0D` → returns error (err=0x01)
- [ ] **P4-17** Stop output on switch: Handle A running → switch to B → A waveform output stops immediately
- [ ] **P4-18** Parameter save & restore: A set 50% current → switch to B → switch back to A → A current restores to 50%
- [ ] **P4-19** Default handle: Power on → read current handle → defaults to Handle A

### 4.5 Current Control (func=0x02)

- [ ] **P4-20** Set current 0% (Handle A) → ACK, waveform output stops
- [ ] **P4-21** Set current 50% (Handle A) → ACK, output current = min + (max-min)×50%
- [ ] **P4-22** Set current 100% (Handle A) → ACK, output current = max
- [ ] **P4-23** Handle parameter independence: A=50%, B=80% → two parameters saved independently
- [ ] **P4-24** Cross-handle setting: Current handle is A, send set B current → B parameter saved, A output unchanged
- [ ] **P4-25** Out-of-range value: Send percent=101 → returns parameter error
- [ ] **P4-26** Current persists after waveform switch: Set 50% → switch waveform → read current → still 50%

### 4.6 Temperature Control (func=0x03)

- [ ] **P4-27** Set temperature 37°C (Handle A): Send `55 AA 07 60 66 44 02 03 25 0A 0D F3` → ACK
- [ ] **P4-28** Set temperature 41°C (Handle A): Send `55 AA 07 60 66 44 02 03 29 0A 0D F6` → ACK
- [ ] **P4-29** Disable heating (temp=0): Send `55 AA 07 60 66 44 02 03 00 0A 9D E9` → ACK, PID disabled
- [ ] **P4-30** Temperature upper limit: Send temp=42 → auto-clamped to 41
- [ ] **P4-31** Handle C no heating: Current handle C, send temp command → returns error or ignored
- [ ] **P4-32** Handle A/B temperature independent: A=37°C, B=41°C → parameters saved independently

### 4.7 Air Pump Control (func=0x04)

- [ ] **P4-33** Pump OFF: Send `55 AA 06 60 66 44 02 04 00 58 CB` → ACK, PB10 LOW
- [ ] **P4-34** Pump ON: Send `55 AA 06 60 66 44 02 04 64 B3 CA` → ACK, PB10 HIGH
- [ ] **P4-35** Pump under Handle A/B: Current handle A, send pump command → ignored or returns error

### 4.8 Start / Pause (func=0x05)

- [ ] **P4-36** Start treatment: Send `55 AA 06 60 66 44 02 05 01 08 0B` → ACK, is_running=1, waveform outputs
- [ ] **P4-37** Pause treatment: Send `55 AA 06 60 66 44 02 05 00 C8 CA` → ACK, is_running=0, waveform stops
- [ ] **P4-38** Idempotent start: Send start twice consecutively → no abnormal behavior
- [ ] **P4-39** Idempotent pause: Send pause twice consecutively → no abnormal behavior
- [ ] **P4-40** Start without params: Power on → send start directly → starts with default params (0% current)
- [ ] **P4-41** Heating persists on pause: Running at 37°C → pause → temperature control continues, heating not interrupted

### 4.9 Waveform Switch (func=0x09)

- [ ] **P4-42** Switch to Waveform 1: Send `55 AA 06 60 66 44 02 09 01 08 0E` → ACK, waveform ID = 1
- [ ] **P4-43** Switch to Waveform 9: Send `55 AA 06 60 66 44 02 09 09 CE 0F` → ACK, waveform ID = 9
- [ ] **P4-44** Iterate waveforms 1~9: Send waveform 1 through 9 sequentially → all switch and ACK correctly
- [ ] **P4-45** Invalid waveform ID (0): Send `func=0x09, para=0x00` → returns parameter error
- [ ] **P4-46** Invalid waveform ID (10): Send `func=0x09, para=0x0A` → returns parameter error
- [ ] **P4-47** Stop on waveform switch: Waveform 1 running → switch to 3 → old waveform stops immediately
- [ ] **P4-48** Current persists after switch: Set 50% → switch waveform → read → current still 50%
- [ ] **P4-49** Default waveform: Power on → read current waveform → defaults to Waveform 1

### 4.10 Shutdown Request (func=0x0A)

- [ ] **P4-50** Shutdown request sent: Long-press power button → MCU sends func=0x0A frame to host
- [ ] **P4-51** Host ACK → shutdown: Host replies ACK → MCU executes full shutdown sequence
- [ ] **P4-52** Host no ACK (timeout): No ACK within 5s → MCU forces shutdown
- [ ] **P4-53** Shutdown while treatment running: Running → shutdown request → outputs stop → then power off

### 4.11 Aging Mode (func=0x07)

- [ ] **P4-54** Enter aging mode: Send `55 AA 06 60 66 44 02 07 01 68 0A` → ACK, aging_mode=1
- [ ] **P4-55** Exit aging mode: Send `55 AA 06 60 66 44 02 07 00 A8 CB` → ACK, aging_mode=0
- [ ] **P4-56** Ignore commands in aging: Enter aging → send start/current commands → no response or returns device busy

### 4.12 OTA Upgrade (func=0x06)

- [ ] **P4-57** OTA start request: Send `55 AA 06 60 66 44 02 06 00 38 CA` → ACK returned
- [ ] **P4-58** OTA during treatment: Running state → send OTA → returns error (device busy)
